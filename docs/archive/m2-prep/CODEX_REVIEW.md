## 必须补齐的实施入口

1. RV64有效地址/PC进入32位PA前规定高位检查，禁止直接截断造成地址别名；明确超范围取指/load/store故障与零总线请求。无C时跳转目标对齐及异常PC也需明确。取指整beat过取可能越过保护范围，后续权限/MMIO约束不能遗漏。
2. commit_valid定义为正常退休；另立trap_valid及interrupt标识，陷阱不加minstret。当前“WB唯一改PC/CSR”与TRAP改PC/CSR冲突，改为明确正常提交和陷阱两条互斥架构更新路径。cause仅5位不足以表达中断标识，需独立位或完整宽度。
3. STAGES的S1漏列mret，但t04实际使用；明确M2-1仅t01–03，异常/CSR归M2-2，并定义未实现编码终止/陷阱行为。补CSR读写、只读访问检查、CSRRS/RC零源不写、计数器与软件写的规则，避免“可读”被误译成非规范只读。
4. reference-run目前只有PASS/周期，没有commit_pc轨迹或minstret起止快照。NEXT_TASKS要求逐条比对/参考退休计数，却未提供提取入口和共同ROI（预载入口vs真实ROM启动、tohost写后循环都不同）。补一个可执行独立参考/确定性期望轨迹方案和小样例；不能以系统周期或被测计数自证。
5. t01的x0反例承诺尚无证据：写x0后CHECK_EQ(x0,0)中的li a1,0通常也读取x0，可能让比较双方同错；修改为不依赖损坏x0的定向检查或由外部架构检查器抓取，提供受控反例证据，不预先承诺检查号1一定失败。
