# M2 实现任务切分（每项可独立验收；首项直接落到执行代码）

前置：Codex 裁定 `DECISIONS.md` 的 D1–D2（语言、乘除）即可开工 M2-1；D3–D7 可在 M2-3 之前给出。

## M2-1：RV64I 执行核 + 独立 CPU 单元 harness（首项，落代码）
- **输入**：`SPEC.md` §2–§4（接口、状态机、**PA 越界检查**、提交/陷入两条互斥路径、提交记录）、`PHYSICAL_PORT_V1`、`tests/` 的 `t01`–`t03` + `t05_roi`（rv64i 变体）。`STAGES.md` 已写明 **M2-1 只覆盖 t01–t03（+t05 的 minstret 可读）**，异常/CSR/`mret` 属 M2-2。
- **授权文件**：`teaching-cpu-work/` 内新建 CPU 源码目录 + `experiments/teaching-cpu/m2/`；不动 m1/m1-soc 已验收资产。
- **产出**：CPU RTL（按 D1 的语言）；一个**不含 SoC** 的 Verilator harness：把 ELF 段预载进一个简单内存模型，物理口直连该模型（可注入 ready/resp 延迟），监视 `tohost`。
- **正向**：`t01`/`t02`/`t03` 的 rv64i 变体退出码 0；三种延迟配置（无延迟 / 固定 / 随机种子）结果逐位相同。
- **故障对照**：至少两个，且**作用在 CPU 上而不是测试上**——(a) 把 `x0` 改成可写的普通寄存器：`t01` 的 `CHECK_X0_ZERO` 必须报错（注意：旧写法 `CHECK_EQ(x0,0,·)` 抓不到，见 `TEST_PLAN.md` §1.1；退出码**不预先承诺**具体数值，因为坏掉的 x0 会影响立即数，只要求"必须失败"并记录实际码）；(b) 去掉 `load` 的符号扩展：`t03` 的检查 2/3 必须失败。**不允许**用超时或编译失败冒充。
- **完成标准**：上述全绿 + 每例记录源码/ELF/二进制哈希与退出码；**`t05_roi` 的 ROI 内 `commit_valid` 计数 == 静态推导的 49**（`tests/expected-trace.py`），且与参考核实测一致；`commit_valid`/`trap_valid` 不同拍。

## M2-2：异常与 CSR
- **输入**：M2-1 的核；`t04`（rv64i）；`STAGES.md` 的 S1 CSR 表。
- **产出**：`TRAP` 状态、M 级 CSR 文件、非法指令检测（未实现编码一律异常）。
- **正向**：`t04` 退出码 0；未对齐访问**零总线请求**（用 harness 的请求计数证明）；访问故障用未映射地址触发，mcause 1/5/7 各一例；**PA 高位非零**与**无 C 时跳转目标 bit1 非零**各一个定向用例（SPEC §3）。
- **故障对照**：(a) 把 `mepc` 写成"下一条指令" → `t04` 的 mepc 检查（exit 90）必须触发；(b) 让某个未实现的 CSR 地址静默读 0 → 新增的负向用例必须失败。
- **完成标准**：`t01`–`t04` 全绿并回归 M2-1 的门禁。

## M2-3：M 扩展 + C 扩展 + 真实 bootrom 启动
- **输入**：D2/D3 的裁定；`t01`–`t04` 的 `rv64ic` 变体；`hello.riscv`（76 条、33 条压缩，已在参考模型跑通）。
- **产出**：乘除单元、C 展开、跨 8 字节 beat 取指、`wfi` 与中断接受。
- **正向**：`rv64ic` 变体全绿；`hello.riscv` 在 CPU harness 上打印三行并 PASS；**接入 M1-soc 的无 CPU 配置替换成本核后，从 0x10040 真实 bootrom 启动**（这一项才允许声称启动链走通）。
- **故障对照**：(a) 把压缩指令的 PC 推进写成固定 +4 → 跨 beat 用例必须失败；(b) 在访存在途时接受中断 → 定向用例必须命中（RW9 的教训）。
- **完成标准**：上述全绿 + `rv64ui-p-*` 与 `rv64um-p-*` 子集通过。
