## 六项裁决

| 项 | 裁决 | 冻结要求 |
|---|---|---|
| A1 | 采用完整A目标，分步实现 | 九种AMO的W/D及LR/SC均为最终目标；不采用默认受限AMO-only路线，不恢复核内两次普通读写。后端先通过，再接CPU；misa.A只在全链支持并验证后置1。 |
| A2 | 采用8字节自然对齐预约集合 | 用物理地址判定，LR.W上下半字、SC字节范围、PutPartial掩码、多拍外部写均须正确；外部写预约集合任一实际字节均可保守失效。不同集合不应被设计成无条件失效。最近一次LR替代旧预约，每次SC消耗预约。 |
| A3 | 有条件采用DRAM汇合后节点 | 所有PL DDR写者必须经过该节点；确切插点、source变换、FIFO域与返回语义要由生成RTL和测试确认。PS保留内存不访问规则是平台前提，不是PL硬件保证；后续上板须核验实际运行配置。当前不扩展MMIO原子，CPU的AMO/LR/SC限定已声明支持的DRAM区域，其他地址返回访问故障。 |
| A4 | 采用并补充分类 | 不支持目标的AMO/SC→7，LR→5，桥不得向目标发请求。未对齐LR→4，AMO/SC→6；page fault分别13/15/15。契约中把LR也概括为6的句子须更正。SC失败也先执行本实现的对齐/翻译/权限/目标检查，避免用sc_fail掩盖异常。 |
| A5 | 有条件采用事务绑定旁带 | 允许此旧TL版本使用内部旁带，但不是“同一时钟域就够”。元数据随已接受请求锁存并保持至对应响应，跨buffer/throttle/broadcast/source变换有准确绑定与assert；不得拿CPU当前输出或硬编码未经证明的source认领Get/Put。sc_fail与D响应共同保持至消费，不得污染普通事务或下一代事务。 |
| A6 | 采用，一事务计数但等待最终完成 | CPU看到一次请求/一次终结响应；AMO内部Get/Put两段不能漏掉后段。重启/hold必须等写完成或错误终结后排空；失败SC无物理写但仍一次响应，预约清除；不在读完成时提前宣布AMO完成或可释放。 |

## 实施前必须纳入的语义（本轮已裁定，不另开泛化规划）

1. **读错误不能继续AMO写。** 本地AtomicAutomata在d_ackd时无条件进入AMO状态并记录error，之后仍发Put，最终才OR错误。因此不可原样复用并宣称“失败无写”。隔离修改/包装须保证原子读返回error时不发后续Put，返回一次原子错误；写阶段error不能承诺撤销已经发生的写，按总线真实保证记录，不重试重复副作用。禁止修改默认Rocket依赖实现。
2. **仲裁与完成点不是一句“Put”即可证明。** 本地cam_abusy只覆盖GET/AMO，ACK阶段放行；其正确性依赖下游FIFO域/请求排序。记录实际Put握手、最终D完成与内存可见顺序，证明已接受先行写与后续读写的顺序；单在途CPU或顺序commit本身不足以证明跨DDR/MMIO的fence。当前允许用更强的串行顺序简化，但需要后端证据。
3. **预约生命周期。** LR在序列化点建立候选预约；LR响应等待期间的竞争写必须能失效，不能在D回来时无条件重新置有效。错误LR不得留下预约；SC成功判定与向受保护下游的实际接受不可留竞争窗口。普通取指、PTW读取不得清预约，否则无TLB核无法保证受限LR/SC循环进展。核心trap/reset清预约的事件通路也须明确（原GATES要求trap清除，但原旁带契约漏了该事件）。故障/不同地址SC同样消耗旧预约。
4. **进展条件。** “TSI/DMA有界”不是已经证明的公平性；声明DRAM的LR/SC进展属性，加入无竞争受限循环最终成功、读/取指/PTW不中断预约、外部写停止后恢复成功测试，确认仲裁不饿死CPU。持续竞争不要求每次SC成功。
5. **权限与排序。** 原子仅使用翻译成功的物理地址，AMO按store类异常检查读写权限及D，LR可按MXR读取可执行页；普通PTW读非原子事务。异常epc/tval/零退休逐项检查。AMO.W/LR.W旧值符号扩展，合法SC返回0/1；W高半字及保持相邻字节必须验证。
6. **失败SC本地响应。** 在共享节点合成D必须与真实D仲裁，source/size/opcode准确，背压稳定，不能覆盖别的master响应或在未接受A时应答。识别外部多拍Put要覆盖实际写掩码与全传输范围。

依据：冻结[A规范v20240411](https://docs.riscv.org/reference/isa/v20240411/unpriv/a-st-ext.html)，结合本地RTL。预约集合、失效与进展条件由规范约束；本项目额外采取trap清除、8字节集合和仅DRAM原子等简化策略。
