# 单发射五级流水核上板报告（PIPE-P3b，中文版）

日期：2026-09-30。板卡：PYNQ-Z1（xc7z020），一次冷上电（boot id `4d45136e…`）内完成全部测量。
英文原版：`REPORT.md`；使用说明：`HANDOFF.md`；原始证据：`results/`。

## 一、结论

1. **流水核在实板上正确运行**：8 个单核裸机门全部通过，xv6 两个工作负载（`m4smoke`、`perf-board`）均通过判定器，
   输出校验和与多周期核完全一致。
2. **时钟实测 40.00 MHz**：用 ARM 侧自己的时钟（与 PL 时钟无关）测得，三次 40.02 / 40.00 / 39.98 MHz。
3. **固定工作量快 1.68 倍（计算）和 3.19 倍（数组）**，与已验收的单核多周期（带 I-cache）相比，同内核、同磁盘。
4. **裸机微基准 IPS**：ALU 循环 20 MIPS（多周期 cache 版 5–6.7 MIPS），I-cache 常驻代码 36.7 MIPS（6.7 MIPS）；
   访存受限的场景提升小（1.4–1.9 倍），因为仍然没有数据缓存、每次只能有一个访存请求在途。
5. **交互环境已交给用户**：板上保留流水核，xv6 已安装、可随时启动（未在运行），用户原来的磁盘已保存。

## 三、时钟频率（独立参考）

方法：两个裸机程序分别让核空转 4,000 万和 8.4 亿个核周期（由核自己的 `cycle` 计数），ARM 用自己的
`/proc/uptime` 计时；两者相减，加载程序的固定开销抵消，f = 周期差 / 时间差。

| 次序 | 频率 |
|---|---|
| 1 | 40.02 MHz |
| 2 | 40.00 MHz |
| 3 | 39.98 MHz |

每次误差约 ±0.1%（受 10 毫秒计时分辨率限制）。同时核对：CLINT 的 `mtime` 恰好等于周期数 / 100，
所以 xv6 里用 `mtime` 算出的秒数有独立依据，不再只是“假定 40 MHz”。

## 五、IPS 对比（板上实测 CPI，MIPS = 40 MHz ÷ CPI）

多周期四个阶段来自 IPS 战役的原始板上样本（baseline → fetch32 → tlb → cache），流水核用完全相同的探针程序，
每格 3 个样本取中位。格式：**CPI / MIPS**。

| 测试循环 | baseline | fetch32 | tlb | cache | **流水** | 流水比 cache |
|---|---:|---:|---:|---:|---:|---:|
| ALU，不分页 | 40.34 / 0.99 | 21.68 / 1.85 | 21.67 / 1.85 | 6.00 / 6.67 | **2.00 / 19.99** | 3.00× |
| ALU，Sv39 1 GiB 大页 | 82.60 / 0.48 | 43.09 / 0.93 | 23.82 / 1.68 | 8.00 / 5.00 | **2.00 / 20.00** | 4.00× |
| ALU，Sv39 4 KiB 页 | 161.28 / 0.25 | 82.61 / 0.48 | 23.82 / 1.68 | 8.00 / 5.00 | **2.00 / 20.00** | 4.00× |
| 32 位指令 | 40.33 / 0.99 | 21.62 / 1.85 | 21.60 / 1.85 | 6.00 / 6.67 | **2.00 / 19.98** | 3.00× |
| 压缩指令 | 21.64 / 1.85 | 21.63 / 1.85 | 21.61 / 1.85 | 6.00 / 6.67 | **2.00 / 19.99** | 3.00× |
| 读 DRAM，不分页 | 46.84 / 0.85 | 27.72 / 1.44 | 27.72 / 1.44 | 11.90 / 3.36 | **7.94 / 5.04** | 1.50× |
| 读 DRAM，4 KiB 页 | 188.18 / 0.21 | 107.63 / 0.37 | 30.45 / 1.31 | 14.74 / 2.71 | **7.94 / 5.04** | 1.86× |
| 读 CLINT | 42.86 / 0.93 | 24.01 / 1.67 | 24.00 / 1.67 | 8.33 / 4.80 | **4.33 / 9.23** | 1.92× |
| 代码装得进 I-cache | 40.33 / 0.99 | 21.70 / 1.84 | 21.70 / 1.84 | 6.00 / 6.66 | **1.09 / 36.67** | 5.51× |
| 代码超出 I-cache | 40.32 / 0.99 | 21.69 / 1.84 | 21.70 / 1.84 | 15.03 / 2.66 | **10.45 / 3.83** | 1.44× |

解读：
- **提升最大**：I-cache 命中时接近每周期一条指令（36.7 MIPS）；3 条指令的 ALU 循环每条 2 个周期，多出的 1 个周期是
  跳转后的取指气泡；TLB 命中时地址翻译不再额外花时间（分页与不分页一样快）。
- **提升最小**：访存（1.5–1.9 倍）和 I-cache 缺失（1.44 倍）。原因是没有数据缓存、同一时刻只有一个访存请求，
  每次访存都要付完整的往返延迟。
- **口径**：以上是短小合成循环的“推导 IPS”（频率 ÷ CPI），不是 xv6 的整体吞吐；板上主机没有指令计数，
  所以两种核都没有“整个 xv6 的 IPS”。最接近真实负载的是第四节的固定工作量结果。
  流水核的 40 MHz 本次独立测过；多周期各阶段用的是配置频率 40 MHz。

- 单流水比单多周期 cache 整机多 3,654 LUT（+25%）、2,143 FF（+31%）；增量几乎全在核内（核 +3,427 LUT / +2,144 FF），

- 三种核都没有用 BRAM 和 DSP：I-cache（1 KiB）和寄存器堆用 LUTRAM，乘除法用 LUT 实现；器件仍有 58% 的 LUT

- 时序：三个最终构建的最差建立路径都在共享 SoC（串口地址 → 原子后端预约比较），不在核内；流水核内部最差路径

- 核内分块数字（见英文版 `../REPORT.md` §5）是跨边界优化后的归属，不是单个特性的代价；前端重设计和流水化在这次
  实现里是一起做的，没有单独拆分对照。

## 八、怎么用（详见 `HANDOFF.md`）

```sh
screen /dev/ttyUSB1 115200          # 回车后看到 /root/xv6run #   （退出 screen：Ctrl-A 然后 k 然后 y）
cd /root/xv6run && ./xv6-pipe.sh    # 启动 xv6，用你的磁盘 fs-user.img
./xv6-pipe.sh /root/xv6run/fs-user-previous.img   # 启动你在双核上用过的那块盘
```
在 xv6 的 `$` 提示符下可以试 `perfcompute`（约 15.8 秒）、`perfarray`（约 12.7 秒）、`mtimetest`、`b0compute`、
`m3par2`、`ls` 等。停止：等到 `$` 提示符后按一次 Ctrl-C；再次运行 `./xv6-pipe.sh` 即可重启。
`fs-user.img` 在两次启动之间保留你的文件，断电后丢失（本机另有用户旧盘的备份）。
