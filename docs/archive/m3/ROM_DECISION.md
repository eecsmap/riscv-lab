# M3 ROM兼容性裁定（Codex，2026-09-15）

采纳方案A：仅教学配置使用专用ROM，把偏移0x54（执行地址0x10054）的32位字0x30301073替换为NOP 0x00000013。原Rocket ROM及其配置不变，不给教学CPU增加mideleg。

## 独立核验与理由

- 直接读取归档镜像偏移0x54，确认为0x30301073：CSR地址0x303、CSRRW、rd=x0、rs1=x0。
- 审计副本和隔离树ROM的SHA256均为3c3ba8317ea4ab3562bb765aedf96931e759ffd15b26a3a82c323ad101a68dc5。
- 核对反汇编：0x10048已经设置mtvec=0x10000；0x10050设置MSIE，0x10058设置MIE，后续WFI/j循环等待。当前CSR译码未实现0x303，默认非法。
- 此处清中断委派是通用启动软件的初始化动作；当前CPU仅M-mode，没有低特权委派功能需要初始化。因此改教学启动软件即可，不应为这一动作改变已验收CPU的CSR集合。

以上是字节/源码核验，不是启动仿真通过。特别注意：原ROM在0x10054非法陷入后，mtvec已指向0x10000，不能未经运行就断言“停在第六条”。它可能错误进入启动入口，绕过等待；原ROM负例应检查非法trap和错误启动顺序，而不是只期待超时。

## Claude实施要求（M3任务内）

1. 新建教学ROM产物及可复现生成脚本，读取原ROM时检查长度156和完整预期哈希、偏移字；不匹配则明确失败。修改只覆盖一个32位指令槽，长度/布局保持不变。保存两份哈希和字节差异；不是要求四个字节必须全部不同。
2. 仅教学配置引用新镜像。生成后核验实际RTL/ROM初始化内容和实际resetVector=0x10040，以及0x1009c设备树布局约定；不能只检验输入文件。
3. 原ROM保留作兼容性负例：证明0x10054产生cause=2、mepc与mtval正确，并不能通过“正常等待MSIP后启动”门禁。修正版应无此异常，必须看到等待、TSI装载、真实MSIP、中断进入与mret后DRAM首条退休的有序证据。
4. CLINT窗口内未实现偏移的读写行为需在真实生成配置验证，不能仅凭地址位于映射窗口便认定不会error；单hart唤醒循环0x2000004读零/退出需要实际日志。
5. 后续引入S-mode时重新评估ROM委派初始化；此补丁不代表完整特权兼容。

不新增阶段阻塞：按本裁定继续M3-a/b/c。长作业及失败产物保留遵循原任务；不运行Vivado、不上板。
