# CPU-SU — the decisions Codex was asked to take (recommendations as delivered)

**Ruled on 2026-09-18: see `CODEX_DECISIONS.md`, which is authoritative.** D-1/2/3/4/5/8/9/10 adopted with corrected
reasons; D-6 adopted as the zero-PMP route with *no* `start.c` change now; **D-7 rejected** (no CPU-internal RMW as
the A extension); two SPEC corrections (SUM read-only 0 at Bare; mip[1,5,9] software-writable at the M address).

| # | Question | Recommendation | Basis / alternative |
|---|---|---|---|
| D-1 | `medeleg` writable mask | **0xB3FF** (causes 0–9, 12, 13, 15) | Spec: bit 11 must be read-only 0; everything else delegable. xv6 writes 0xffff and works either way: the port's `timervec` *reflects* non-delegated traps in software, so with the wide mask that path becomes dead code and the M-mode surface shrinks. Alternative: Rocket's 0xB109 (misaligned fetch, breakpoint, ecall-U, page faults) — keeps bit-for-bit parity with the board Rocket, costs nothing in hardware either way (one mask). su09 expects 0xB3FF. |
| D-2 | `satp` at the Bare-only step | MODE ≠ 0: whole write ignored; MODE = 0 with nonzero fields: stored as 0 | Spec text for unsupported MODE ("the entire write has no effect"); for MODE = 0 the spec says software must write zeros and leaves other patterns unspecified — storing 0 is the least surprising legal choice. Consequence to state plainly: **xv6 cannot run at this step** (its `MAKE_SATP` write would be silently ignored); that is the Sv39 task, not a stub here. |
| D-3 | `MPP` written with the reserved value 2 | store 0 (U) | WARL lets us pick any legal value; U is the value `mret` leaves anyway. Rocket legalises to the same. |
| D-4 | `TVM`, `TSR` | hardwired 0 | xv6 never sets them; both only matter to a hypervisor-like M that wants to trap S's `satp`/`sfence.vma`/`sret`. Real bits could be added with Sv39 if ever needed; hardwiring is spec-legal. |
| D-5 | `TW` and `wfi` in S/U | hardwired 0; `wfi` stays a legal no-op in all modes | xv6 has no `wfi`. Spec allows U-mode `wfi` "if it completes within a bounded time" (ours: immediately). Reference divergence: qemu makes U-mode `wfi` illegal, Rocket allows it — both legal. Not tested as a gate (see TEST_PLAN). |
| D-6 | PMP: xv6 `start.c` writes `pmpaddr0/pmpcfg0` | **Do not implement PMP CSRs (illegal instruction), and change two lines of `start.c`** when the xv6 task starts (the port already patches `start.c` for the missing `menvcfg` in exactly this way). With zero PMP entries the spec grants S/U every access, so this is correct, not a hole. | Alternatives: (i) writable, effect-free registers — rejected by the delegation ("no fake PMP"); (iii) a real 1-entry TOR/NAPOT PMP with checks on every fetch/load/store in S/U — about a comparator per access plus the CSRs; only worth it if something other than xv6 must run. Recorded requirement either way: after writing PMP CSRs software must `sfence.vma` (spec; the Rocket model caches PMP results in its TLB — found the hard way in `ref-run` debugging). |
| D-7 | Atomics for xv6 (`amoswap.w(.aq)` ×4, `lr/sc` ×0) | Implement in a separate task **all RV64 AMOs (w/d) as a CPU-internal read–modify–write on the single port**: one read, the ALU op, one write, no other request and no interrupt between; plus `lr/sc` with a single-hart reservation that fails on any intervening store, trap or `sc` to another address. State the boundary as a *contract*: atomicity holds against this hart's instruction stream only; external masters (TSI, block-device DMA) never touch lock words (M0 audit) and this remains a requirement on software placement, not a property of the bus. | Alternative: TileLink `Arithmetic/Logical` through `TLAtomicAutomata` in the adapter — real bus atomics, but it changes the shared `ZynqAdapter`/TileLink client (frozen area) and the AXI memory port does not execute atomics natively. Implementing only `amoswap` is rejected: a different compiler flag would silently need more. |
| D-8 | `time` CSR (0xC01) | not implemented at this step (illegal); `mcounteren.TM` read-only 0 | xv6 never reads `time` (`r_time` unused); providing it needs the CLINT `mtime` value inside the core (a 64-bit input port from the SoC). Cheap to add later with Sstc if ever wanted. |
| D-9 | The teaching ROM's NOP'd `mideleg` write | leave the patched ROM; note that the original ROM would now also boot | Reset value of `mideleg` is 0 either way; no artefact changes in this task. |
| D-10 | `sie`/`sip` as views vs. separate registers | views (`mie & mideleg`, `mip & mideleg`) | Spec semantics; xv6 writes `sie` in M *after* `mideleg`, and `sip` from both M and S — a separate copy would desynchronise. |
