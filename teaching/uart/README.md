# UART：MCU-0 和 PC 说话

MCU-0 加一个串口（UART），通过一个 USB 转串口模块接到 PC。有了它，板子上的程序可以打印文字、接收命令，
以后还能从 PC 直接下载程序，不用每次重新生成比特流（引导程序，见 `docs/TODO.md` 的 B 部分）。

## 接线

PYNQ-Z1 板上的 USB 串口接在 ARM 那一侧（PS），MCU-0 所在的 FPGA 逻辑（PL）用不到，所以要一个外接的 3.3 V
USB 转串口模块。这里用的是 Adafruit FT232H 转接板；任何 3.3 V 的 USB 转 TTL 串口模块都可以（**不要用 5 V 的**）。
接在 Arduino 排针的数字脚 D0、D1 上（不是模拟脚 A0、A1），不占 Pmod 口，VGA 和摇杆都不用拔：

| FT232H | PYNQ-Z1 | FPGA 管脚 | 方向 |
| --- | --- | --- | --- |
| D0（TX） | **D0**（RX） | T14 | PC → MCU |
| D1（RX） | **D1**（TX） | U12 | MCU → PC |
| GND | GND | | 共地，必须接 |
| 5V | 不接 | | 两边各自供电 |

- 数据线要**交叉**：一边的发送接另一边的接收。Arduino 排针上的名字是从板子的角度说的：D0 = RX，D1 = TX。
- **先给板子上电，再接 FT232H 的 D0 线**（至少在 PC 开始发送之前）。FT232H 的 TX 空闲时是 3.3 V，板子没电时这个电压会
  经过输入保护二极管漏进 FPGA（反向供电）。在这根线上串一个 1 kΩ 电阻就更安全。
- 避开 D2（U13）：它同时是 FPGA 上电配置时用的 `PUDC_B` 脚。
- `pynq-z1.xdc` 给 D0 开了上拉：没接线时引脚停在空闲电平（高），不会被当成一串起始位。

PC 上它是 `/dev/ttyUSB0`（更稳妥的名字：`/dev/serial/by-id/usb-0403_6014-if00-port0`）。不接板子、把 FT232H 的 D0 和
D1 短接，就能自检：发出去的字节原样收回来（实测 115200、1 M、3 M 波特都对）。

## 串口怎么传一个字节

线空闲时是高电平。一个字节 = 1 个低电平的**起始位** + 8 个数据位（**低位在前**）+ 1 个高电平的**停止位**，
每一位持续同样长的时间。这叫 8N1（8 位数据、无校验、1 位停止位）。没有时钟线：两边各自按约好的速率（波特率）计时。

```
空闲 ‾‾‾‾‾|_起始_|_d0_|_d1_|...|_d7_|‾停止‾|‾‾‾ 空闲（或者下一个起始位）
           ↑ 下降沿：开始计时
               ↑ 半位之后：起始位中间，还是低才算数
                     ↑ 之后每隔一位采一次：每一位的正中间
```

115200 波特下一位约 8.68 µs；时钟 40 MHz，所以一位 = 40,000,000 / 115,200 = 347.2 拍，取 347（快 0.06%）。
一个字节 10 位，约 87 µs，够我们的核执行几千条指令，轮询完全来得及。

**为什么在正中间采样。** 两边的时钟不可能完全一样快。接收方从起始位的下降沿开始计时，误差每一位都在累积，
到停止位（第 10 位）时累积得最多。只要累积的误差不到半位，正中间的采样点就还落在正确的那一位里。
粗算：9.5 位里攒的误差不能超过 0.5 位，大约 5%。

测试平台实测（我们一位 347 拍，PC 模型逐渐放慢）：PC 一位 **366 拍**（慢 5.5%）还全对，**367 拍**就错。
可以精确算出来：接收方在下降沿之后 2 拍同步 + 1 拍判断 + 173 拍（半位）+ 9 × 347 = 3299 拍时采停止位；
PC 的停止位从 9 × P 开始，所以要 9P < 3299，P ≤ 366。理论和仿真对上了。

## 硬件：`mcu_uart`（`teaching/mcu0/mcu_uart.v`）

- **发送：** 一个等待槽（`thr`）加一个移位寄存器。CPU 把字节写进等待槽，前一个字节还在线上也没关系；
  移位寄存器空了就从等待槽取下一个，所以字节之间没有空隙。
- **接收：** 引脚先过**两级触发器同步器**（PC 的信号什么时候变都有可能，和我们的时钟无关，见问答库里亚稳态那一条），
  然后按上图找起始位、在每一位中间采样。停止位是低 → 帧错误；上一个字节还没被读走 → 溢出，新字节丢掉。
- 都是 64 位寄存器，基址 `0x1005_0000`，4 KiB 窗口：

| 地址 | 名字 | 内容 |
| --- | --- | --- |
| +0x00 | TX | 写：要发送的字节（第 0 字节通道）。等待槽满时写入会被丢掉，并置 TX_OVERFLOW，所以要先看 TX_READY |
| +0x08 | RX | 读：第 8 位 VALID，第 7..0 位是字节。**读一次就拿走**：VALID 清零，直到下一个字节到来 |
| +0x10 | STATUS | 读：0 TX_READY（等待槽空）、1 TX_IDLE（全部发完）、2 RX_VALID，以及三个粘滞错误位：3 RX_OVERRUN、4 RX_FRAME、5 TX_OVERFLOW。写第 0 字节通道：清三个错误位 |
| +0x18 | DIV | 读写：每位多少拍，复位值 347（115200 波特）。小于 4 按 4 算 |

**RX 为什么"读一次就拿走"，而且 VALID 和数据在同一个字里。** 如果先读 STATUS 看有没有、再读 RX 拿数据，两次读之间
可能又来了一个字节，或者别的代码先拿走了。一次读同时给出"有没有"和"是什么"，就没有这个窗口。代价是：**读 RX 有副作用**，
调试器或者多余的一次读都会吃掉一个字节（问答库 `2026-10-22-mmio-register-semantics`）。

## 固件

`teaching/mcu0/uart.h`：`uart_putc`（等 TX_READY 再写）、`uart_getc_nb`（没有就返回 -1）、`uart_getc`（等到有为止）、
`uart_puts`（`\n` 发成 `\r\n`，终端需要回车 + 换行）、`uart_putdec`、`uart_puthex`。全部轮询，不用乘除法。

`uart_echo.c`：开机打印一行提示和提示符 `> `，然后收到什么就发回什么，小写变大写（证明数据经过了 CPU，而不是线直接连回来）。
回车结束一行，报告这一行几个字符。终端按回车可能发 `\r`，也可能发 `\r\n`，两种都只算一次。
LED0 心跳（约 2.4 Hz），LED1 每收到一个字节翻转一次，LED2 = 出现过接收错误（溢出或帧错误），LED3 = 至少收到过一整行。

## 仿真

```sh
cd teaching
make uart-sim CORE=../rtl/cpu       # 约 35 秒
make uart-sim CORE=work/cpu         # 你的核
make uart-sim UART_PC_DIV=367       # PC 慢 5.8%：超出容限，应该失败
```

`tb_uart.v` 在两根线的另一头放了一个"PC"：它解码 `uart_tx` 上的每个字节（同样在中间采样，并检查停止位），
看到第一个提示符后打 `hello, mcu` + 回车（CR），看到第二个后打 `ab` + CR LF。字节**一个接一个、中间没有空隙**，而且默认
**比我们慢 3%**（一位 358 拍）。收到的全部文字必须和期望的 118 个字节逐字节相同；最后一个提示符之后再等 4 个字节的时间，
多出来的东西（比如多一行）也会被抓到。还要求没有帧错误、没有总线错误、没有同步异常，LED3 亮、LED2 灭。

### 变异体（每个都必须失败，且失败原因对）

| # | 改了什么 | 失败原因 |
| --- | --- | --- |
| 1 | 接收在每一位的开头采样，而不是中间（起始位等 1 拍而不是半位） | 第一个回显的字节就错（收到 0x95，应为 `H`），LED2 亮（帧错误）。**PC 和我们一样快（`UART_PC_DIV=347`）时它能通过**：所以测试故意让 PC 慢 3% |
| 2 | 发送高位在前 | 第一个字节就错（收到 0xB0，应为 0x0D） |
| 3 | 读 RX 不拿走字节（VALID 不清零） | 固件把同一个字节当成源源不断的新字节：一直回显 `H`，收到 576 个字节而不是 118 个，LED2 亮（溢出） |
| 4 | 固件：CR LF 算两次回车 | 多出一行 ` (0 chars)`：收到 120 个字节而不是 118 个 |

## 上板

```sh
cd teaching
make mcu0-bit APP=uart_echo CORE=work/cpu && make mcu0-prog APP=uart_echo
python3 -m serial.tools.miniterm /dev/ttyUSB0 115200     # pyserial 自带的终端；Ctrl+] 退出。也可以用 picocom / screen
```

板子烧好时会打印提示；终端打开得晚就没看见，按 BTN3 复位一下再打印一次。这个版本 `PMOD_VGA=0`：接着的显示器没有信号，正常。

**2026-11-07 上板结果（学生核，WNS +9.784 ns，无严重警告）：** 烧写后 13 秒收到完整的提示行和 `> `；
`hello, board` + CR 回来 `HELLO, BOARD (12 chars)`；`abc xyz 123` + CR LF 回来 `ABC XYZ 123 (11 chars)`（CR LF 只算一次）；
95 个可打印 ASCII 字符一口气连着发，原样回来（小写变大写）并报告 `(95 chars)`。

## 练习

1. 用 `make uart-sim UART_PC_DIV=...` 自己找出容限的两头（PC 更快时呢？试 `330`、`328`）。和上面的公式对一下。
2. 把起始位的"半位"改成四分之一位，容限变成多少？哪一边变差了？
3. 去掉同步器（直接用 `rx`），仿真还能通过吗？为什么仿真抓不到？板子上可能出什么错？（和 VGA 练习 7 对比。）
4. 一次粘贴很长一段文字，看 LED2：为什么会溢出？给接收加一个 8 字节的 FIFO（参考 `mcu_spi.v` 的发送 FIFO），再试。
5. 把波特率提高到 1 Mbaud：DIV 写 40，PC 用 `miniterm /dev/ttyUSB0 1000000`。还能更快吗？瓶颈在哪一边？
6. 加一个偶校验位（8E1）：发送和接收各要改什么？测试平台呢？
