# 可替换执行核的多核实验方案

日期：2026-09-25。状态：设计方案，未开始 RTL 实现或硬件操作。

## 1. 目标与范围

学习目标：分别观察执行组织、核数、存储系统对正确性和性能的影响。
首个交付：PYNQ-Z1 上两个多周期 RV64 hart 运行同一个 xv6 内核，共享内存，能并发完成计算任务。
保持当前 fetch32、每核 8 项 TLB、每核 1KiB I-cache；不引入 D-cache、流水线、乱序或新的内存控制器。
按 N 核组织，但第一阶段只承诺 1/2 核；4 核先做 elaboration/仿真扩展检查，不承诺上板。

未来配置矩阵：CORE_IMPL=multicycle|pipeline，NUM_CORES=1|2|4。
尚未实现的组合必须明确报 unsupported，不能静默替换为多周期实现。
使用构建配置切换，不是运行时热切换。

## 2. 起点和已知约束

- 参考冻结点：ips-v1-icache，c16306bcfb40ead07a0375826527e9b871997f37；实施前验证 tag、源码及构建 manifest 对应关系。
- 参考 RTL：worktrees/ips-cache/rtl/cpu/tcpu_core.v。已有物理单口、AMO/LRSC 字段、resv_clear、退休/异常观察及每核中断输入；尚无这里计划的通用 hart 封装。
- 原子后端历史设计：riscv-lab/docs/archive/cpu-atomic-backend/DESIGN.md，当前单 CPU source/单预约假设必须审计和泛化。
- xv6 存在 NCPU 和每核初始化结构，不代表板级移植已可多核运行。须审计实际部署内核，不能以仓库另一副本代替。
- 当前整机 14554 LUT、7011 FF，0 BRAM/DSP 是单核整机资源，不可当作每核面积。40MHz 是目标，不是双核时序保证。
- 当前板已交给用户交互使用；本方案不授权访问串口、覆盖磁盘或烧写。换 bitstream 继续遵守物理断电重启与租约规则。

## 3. 模块边界

Hart wrapper 统一 RESET_PC、HART_ID、中断、物理请求/响应、预约清除、退休/异常观察接口。
wrapper 内包含执行核及其私有翻译/取指结构；本轮不为追求形式统一而大搬移现有 TLB/PTW/I-cache。
未来流水线实现复用这些模块或遵守相同参数与行为，禁止外层引用内部状态机或级间信号。

每 hart 独立 bridge，进入统一仲裁与共享原子后端，再复用 TL—AXI—PS DDR 路径。
具体挂接位置在 M0 以当前 Scala 图和所有内存写入来源审计确认；不能留下绕过原子保护的并发写路径。

### 统一端口契约

- 保持当前 req/resp 两套 ready/valid，字段沿用 PHYSICAL_PORT_V2；地址与写数据在同一请求。
- valid 一旦提出，握手前不得撤销或修改负载。响应背压时同样保持。
- 响应最早在请求握手的下一周期出现；每 hart 最多一笔在途，唯一响应且不得串核。
- hart/source 标识由实例和 bridge 路由携带，不要求 CPU 增加事务 ID。不得假设 hart ID 等于 TL source ID。
- 仲裁锁住已提出且尚未握手的选择；AMO 不在读写两半之间释放原子保护。
- 第一版共享后端全局串行完成内存事务，接受其吞吐限制。公平性在下游最终响应、各消费者最终接收的前提下证明/测试。
- 不支持单 hart 热复位：首版统一 quiesce/drain 后复位所有 hart。不得靠复位丢弃已提交写事务。

### 原子性和顺序

- 每 hart 独立 LR/SC 预约，以现有 8-byte granule 为起点，记录归属及有效位。
- 其他 hart 或可并发外部 master 的重叠写必须使相关预约失效；SC 的检查与提交不可被其他写插入。
- 核本地 trap/reset 清除自己的预约；全系统 reset 清全部。错误路径不能报告成功 SC。
- LR 失败、SC 成败、AMO 读错不写、AMO 写错一次报告、字宽/符号扩展和 partial store 重叠都须测试。
- 以事务完成点及互连顺序定义可见性，不能仅凭 req.fire 顺序宣称内存顺序已满足。
- 审计 aq/rl、FENCE、FENCE.I、SFENCE.VMA 与 satp。第一版可采用比 ISA 更强的串行化约束。
- 主机 loader/磁盘路径是否直接写目标 DDR 必须查明；若无法参与预约协调，限定其运行时写入范围/所有权，禁止并发修改普通共享内存。

### 启动、软件和维护操作

- HART_ID 0/1，真实 mhartid；每核独立寄存器、CSR、栈、TLB、I-cache、mtimecmp/msip 等适用状态。
- hart0 执行全局初始化，其他 hart 按实际 xv6 启动协议等待，再进入各自调度器。
- 中断控制器目标上下文及设备中断路由按现有平台审计；不能只把同一根中断线复制两份。
- fesvr/tohost、磁盘请求及完成队列必须避免双核重复处理；可先指定 hart0 服务，但不能破坏其他核唤醒和进度。
- 本地 SFENCE.VMA/FENCE.I 不是跨核广播。审计 xv6 页表变更、迁移和 exec 的可见性；需要的远程失效/同步不得用“暂不支持动态代码”掩盖普通 exec 正确性。

## 4. 未来流水线约束

流水线可保持同一物理单口与每 hart 单在途，先接受结构冲突，不绑定到新总线。
已提出请求不得因分支 flush 撤销；错误路径取指响应完成后丢弃，不提交异常。
store/AMO/有副作用 MMIO 仅在不会成为错误路径时发出；退休与异常精确。
预测性取指限制在明确允许的普通内存区域。CSR/中断和多周期执行单元在核内处理。
新流水线先单核验证，再进双核回归。新增在途深度、I/D 双口、D-cache 均另立实验。

## 5. 阶段与硬验收

### M0：契约和可行性审计（首个任务包）

交付 CONTRACT.md、接口/修改点清单、资源分层表、测试矩阵、软件与 host 单核假设清单。
逐项决定 source/hart 映射、原子保护范围、预约事件、启动入口、中断、host 内存写、跨核维护、全局复位。
读取真实分层报告，区分共享与每核资源；面积估计标为估计。识别部署内核/磁盘的来源和 hash。
验收：以上每项有代码证据和明确决策，无未决的正确性问题才能进入 M1。不操作板、不大改 RTL。

### M1：可替换 wrapper，单核不退化

只实现 multicycle/1。运行既有 ISA、异常、Sv39/TLB、I-cache、原子和背压回归。
对同一输入比较退休序列/异常/内存效果，不要求异步事件下逐周期相等；定向确定性场景另查周期变化。
坏配置明确拒绝；外层没有 tcpu FSM 状态依赖。记录 wrapper 带来的任何性能变化。

### M2：双核互连和原子后端

先用两个独立协议驱动器，随机请求/响应背压和延迟，再接真实核。
验收：无错投/丢失/重复响应，握手稳定；每 hart 单在途；等待有条件公平。
定向覆盖双核同址 AMO、双 LR 后竞争 SC、其他核 partial write 清预约、不同 granule、trap 清除、错误和全局 drain。
至少 10 个固定随机种子，每种至少 10000 笔完成事务；超时/未闭合事务即失败。
负向注入至少覆盖错误路由、漏清预约、AMO 间插入写、valid 撤销，检查器必须检出。

### M3：双核裸机与 xv6 仿真

裸机验证独立 hart/栈、每核中断、锁保护计数器、消息传递发布/获取及双核长期进度。
xv6 验证两核进入调度器且都实际运行用户工作；覆盖 exec/fork/wait、迁移、内存分配、磁盘和应用校验。
单核配置继续通过。4 核至少 elaboration 和小型仲裁/原子测试，不列为板上完成。

### M4：双核构建与上板

正式综合/布局布线，目标 40MHz、setup/hold 全通过、无新增未解释 critical warning；报告 LUT/FF/BRAM/DSP。
若失败，先报告时序路径/面积瓶颈再决定调整，不静默降频来宣称对照成立。
板操作另行协调用户交还串口和断电重启。先启动门禁，再双核 xv6 和 M3 关键测试。
保留单核已验证镜像及明确的恢复步骤，不覆盖历史证据或用户交互磁盘。

### M5：最小收益测量与结案

一个父进程启动固定四份计算并 wait 全部结束；数组负载同理，使用独立地址空间。
固定总工作量，在 1/2 核相同频率和每核 cache/TLB 配置下各跑至少 3 次。
报告正确性、耗时中位数/范围、吞吐、S2=T1/T2、E2=S2/2、资源增量；不设置强制接近 2x 的验收指标。
主指标为完成时间；若读计数器，要使用全局一致时间源或记录迁移，禁止对不同 hart 的 instret 直接作差。
每核退休量与等待/仲裁事件作为解释辅助，不能把自旋退休当有效工作。
交付报告、原始记录、构建/软件标识和复跑入口。双核稳定后暂停扩展，转入单核流水线实验。

## 6. 管理和完成定义

独立 worktree/分支，不切换共享 checkout，不修改既有 ips-v1-* tag。
Codex 维护契约/裁决并独立验收；Claude 可分阶段实现，阶段任务通过 coord 单独下达。
本文件不是已经下达的实现任务，也不是烧写许可。建议第一包仅 M0，避免一次派发到上板造成范围漂移。
每阶段只维护一份报告和一份验收记录，避免重复框架。估计与实测分栏，失败证据保留。
阶段 tag 可采用 mc-v1-single-wrapper、mc-v1-dual；仅在验收且用户同意发布后创建/推送。

首轮完成定义：可配置单/双多周期核、双核 xv6 正确运行、两类负载的可复现扩展数据、未来流水线接口明确。
不包括四核板验收、流水线实现、D-cache、一致性协议或通用性能测量平台。
